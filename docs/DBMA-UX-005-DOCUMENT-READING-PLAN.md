## 1. 배경

DBMA-UX-004 점검 중 확인된 것: `document_reading.html` 목업이 상정한
"문서를 열어 본문을 읽고 AI 어시스턴트와 함께 분석하는" 화면이 라이브
앱 어디에도 없다.

- Library 문서 상세 패널은 메타데이터(제목/유형/크기/경로/수정일)만
  표시 — 본문 없음
- Research 페이지는 AI 인사이트 카드와 120~300자 짧은 발췌만 표시 —
  전체 본문 없음
- 처리된 문서의 전체 텍스트(`data/제련완성본/*.md`)를 사용자가 읽을
  방법이 현재 UI에 전혀 없음

즉 목회자가 "정리된 자료"를 실제로 펼쳐 읽을 화면 자체가 빠져 있다.
Sample Library(UX-003)와 마찬가지로 목업에는 있었지만 구현되지 않은
진짜 기능 공백이다.

## 2. 목표

처리 완료된 문서(Library의 "정리된 자료")를 클릭하면 원문 전체를 읽을
수 있는 화면을 제공한다.

## 3. 착수 전 HQ 결정 필요

### 3.1 어디에 만들 것인가

- **옵션 A — Library 상세 패널 확장**: 기존
  `_render_document_detail_panel()`에 "본문 읽기" 섹션(또는 expander)을
  추가. 장점: 새 페이지/라우팅 불필요, 문서 선택 흐름 재사용. 단점: 긴
  본문을 읽기엔 사이드바+메타데이터 패널이 있는 좁은 레이아웃이 불편할
  수 있음
- **옵션 B — 독립된 새 페이지**: `ui/pages/document_reading.py` 신설,
  목업처럼 넓은 리딩 컬럼 + 우측 AI 어시스턴트 패널 레이아웃. 장점:
  목업 의도(넓은 리딩 경험)를 제대로 살림. 단점: 사이드바 내비게이션에
  새 항목 추가 필요, 페이지 간 이동(문서 선택 → 읽기 화면) 로직 필요

**본 Task Order는 옵션 A를 기본 전제로 작성한다** (범위가 작고 기존
흐름과 자연스럽게 이어짐). 옵션 B를 원하면 착수 전에 알려줄 것.

### 3.2 AI 어시스턴트 패널을 포함할 것인가

목업에는 "방금 읽은 부분 요약", "내서재에게 물어보세요" 같은 AI
어시스턴트 사이드 패널이 있다. 이건 실제 RAG 파이프라인 연동이 필요한
별도 기능이라 **본 Task Order 범위에서 제외**하고 "본문 읽기" 자체만
먼저 구현한다. AI 어시스턴트는 필요 시 후속 Task Order로 분리한다.

## 4. 범위

### 포함
1. 문서 선택 시 처리된 본문(`{output_dir}/{stem}.md`)을 읽어 표시하는
   섹션 추가 (Library 상세 패널, `_render_document_detail_panel()` 내)
2. 긴 본문에 대한 가독성 처리 — 목업의 `reading-column`(720px 상당)
   개념을 살려 본문 영역 폭 제한, 줄간격 확보
3. 원본이 아직 처리되지 않은 문서(md 없음) 클릭 시 적절한 안내
   ("아직 처리되지 않았습니다" 등, Dead End 없이 "자료 등록으로 이동"
   유도)

### 제외
- AI 어시스턴트 패널 (§3.2)
- 문서 내 검색/하이라이트 등 부가 기능
- 별도 페이지/라우팅 신설 (옵션 A 전제)

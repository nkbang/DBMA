## S6-2 — P0-5 대표 질의 24건 인적 채점

**실행은 사용자만 할 수 있는 임계 경로다.** CUE가 준비할 수 있는 것은
"채점할 자료를 최신·정확하게 만들어 두는 것"까지다.

### 이번에 한 일

1. `scripts/p0_5_run_all.py`(2026-09-18, 이 세션 이전에 이미 작성됨)를
   **재실행** — 사이드카 메타데이터 백필(PR #55·#60)과 orphan 레코드
   정리(별도 세션) 이후 상태로 24건 답변을 다시 수집했다. 기존 결과
   (`docs/NAE_GOLD_QUERY_SET_P0_5_RESULT_001.md`, 2026-09-18 작성)는
   "인용 출처 메타데이터 90건 중 74건 비어 있음"이라고 기록돼 있었는데,
   이는 사이드카 백필 **이전** 상태다 — 지금 다시 돌리면 인용이 훨씬
   많이 채워질 것으로 예상되어 재실행이 필요했다.
2. 결과: `docs/NAE_GOLD_QUERY_SET_P0_5_RAW_ANSWERS_001.json`,
   `docs/NAE_GOLD_QUERY_SET_P0_5_RESULT_001.md` 갱신(아래 §실행 결과
   참고).

### 채점 방법 (기존 안내, 변경 없음)

1. 채점 도구(Artifact,
   `docs/NAE_GOLD_QUERY_SET_P0_5_001.md` 문서 상단 `scoring_tool` 링크)를
   연다.
2. `docs/NAE_GOLD_QUERY_SET_P0_5_RESULT_001.md`에 정리된 24건 답변을
   보면서 8개 축(자료 충실성·신학적 정합성·출처 투명성·문맥 보존·목회적
   유용성·언어 완성도·불확실성 정직성·신학적 혼합 방지)으로 채점.
3. 정직 유보 답변(근거 0건 인정)은 슬라이더 무시하고 수동 PASS.

### 채점 시 특히 봐야 할 것 (과거 실측에서 나온 결함, 재현 여부 확인)

  전통에서는..." 같은 근거 없는 진술이 관측된 바 있음
  ([[project_p0_5_a1_grounding_leak]]). 재현되면 FLAG/FAIL.

  §2가 막아야 하는 패턴, 과거 1회 재발 관측.
- **문자 오염** — 한자·키릴 등 재시도 소진 케이스가 과거 24건 중 6건

## S6-3 — 외부 목회자 3~5명 실기

**S6-1(R4)에서 만든 GitHub Release 자산이 실제로 발행돼야(S6-4)
테스터가 빈 서재가 아닌 상태로 설치할 수 있다 — 이 순서가 먼저다.**
그 전까지는 아래 자료만 준비해 둔다.

### 준비한 것

**테스터 안내 Artifact** — 설치→설교 1편 작성→피드백까지 단계별 안내 +
질문 7개(R6 기준 매핑) + "질문 복사" 버튼(카톡/문자로 바로 붙여넣기).
링크: https://claude.ai/artifact/3kM2vnbGFxPT6yHXTJcMzr
(**비공개 상태 — Share 메뉴에서 테스터에게 개별 공유해야 열람 가능**,
CUE는 공유 권한을 바꿀 수 없음)

이 Artifact는 **db/artifact 저장 기능을 쓰지 않았다** — 외부 링크로
받는 익명 방문자는 claude.ai 조직 밖이라 실시간 저장·양식 제출 기능에
쓰기 권한이 없다(확인된 플랫폼 제약). 그래서 "질문 복사 → 본인이 쓰는
채널(문자·카톡·이메일)로 David에게 직접 답장" 방식으로 설계했다 —
테스터 3~5명 규모에는 이게 더 확실하다.

### [2026-09-25 갱신] S6-4 완료 확인 — S6-3 착수 가능

  **수정 불필요.**
- **코퍼스 디코딩 점검**: 과거(2026-09-07) 관측된 TSU `UnicodeDecodeError`

  `errors="replace"` 미적용)가 현재 로컬 `output/bench/tsu_dataset.jsonl`

  안 고쳐졌으니 향후 비-UTF8 소스가 다시 섞이면 재발 가능 — 근본 수정은

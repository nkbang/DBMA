# J6 — 생성 모델 A/B 실측 (2026-10-18)

조건 ④(한국어 문법·문학적 완결 문장)의 남은 원인은 필터가 아니라 **생성
모델**이라는 J1 결론을 검증한다. `core/generation.py`의 오염 방어는 이미
설계 한계에 가깝고(문자 체계 9종 + 라틴 문맥 판정 + 재시도 2회 + 표식·고지),
J1에서 B2 답변의 **핵심 신학 용어 자리에 표식 17자**가 박혔다.

## 1. 통제 조건

| 통제 | 방법 |
|---|---|
| 근거 동일 | 질의당 검색 **1회**만 돌려 같은 `ResponsePackage`를 모든 모델에 넘김. 1·2차 모두 전 질의 근거 5건으로 재현 |
| SYSTEM 동일 | 현행 모델의 SYSTEM 전문을 후보에도 입힌 파생 모델 생성(`nae-gen-qwen38:ab`, `nae-gen-qwen36:ab`) — 그대로 비교하면 모델이 아니라 프롬프트를 비교하게 된다 |
| 생성 옵션 동일 | `_gen_options()` 공유(temperature 0.2 · repeat_penalty 1.3 · num_predict 1024) |
| 코드 경로 동일 | `GenerationService.generate()` 그대로 — 오염 탐지·재시도·표식·ClaimGuard 전부 포함 |

## 2. 1차 실행이 드러낸 선결 결함 — thinking 모델

1차에서 후보 2개의 **중위 답변 길이가 0자**로 나왔다. 모델 품질이 아니라
호출 방식의 문제였다. 직접 확인:

```text
nae-gen-qwen36:ab, num_predict=1024
  → thinking 3,850자 / response 0자 / done_reason="length" / eval_count 1024
  → think=False 로 재호출: response 233자 / thinking 0자 / done_reason="stop"
```

qwen3 계열은 thinking 모델이고 `num_predict`가 사고 과정에 전량 소진되면
`response`가 빈 문자열이다. `generate()`는 `result["response"]`만 읽으므로
답변이 통째로 사라진다. → `generate(think=...)` 패스스루를 추가하고(생략 시
종전과 **바이트 단위 동일** 호출, 테스트로 고정) 후보를 재측정했다.
**1차의 후보 수치는 무효**다.

### 3.1 후보2(qwen3.6 MoE) — 기각

- 표식 31자로 현행(35자)과 사실상 동급이고 오염 이벤트는 24회로 **더 나쁘다**.
- **유보 규율이 약해졌다**: 현행이 유보한 질의 2건(A3·D3)에 답했고, 그중
  D3는 **출처 표기가 없다**. 조건 ①(자료 밖 지식 혼입 차단)은 유보가
  제대로 작동할 때만 지켜지므로 이 방향의 변화는 받아들일 수 없다.
- 지연은 가장 빠르다(p50 11.9s). 속도만으로 선택할 이유는 없다.

### 3.2 후보1(qwen3.8 Q8 dense) — 실질 개선

- **표식 35자 → 3자 (91% 감소)**. 사용자가 실제로 받는 답변의 손상이
  거의 사라졌다. J1의 B2처럼 핵심 용어가 □로 지워지는 사례가 없다.
- **유보 규율이 약해지지 않았다**: 현행이 유보한 질의에 **추가로 답한 것
  0건**. 오히려 더 보수적이다(유보표현 19 vs 13).
- **답할 때는 전부 출처를 밝힌다(5/5)**. 현행은 9/11.
- **일반지식 어구 0건**(현행 1건 — "일반적으로" 류, `_GROUNDING_DIRECTIVE`
  §2가 막으려는 표현).
- p90 지연 141.0s → **69.4s (0.49배)**. 70B보다 빠르다.
- 답변 품질(B1 실례): 소제목으로 구조화, 문장마다 출처 병기, 원어 괄호
  병기, 완결된 경어체. 교단 정합성 선언(J3-b 금지 대상) 없음.

## 4. 게이트 G6 판정 — 문자 그대로는 미충족, 의도로는 충족

계획서 G6: "오염 이벤트가 현행 대비 **1/3 이하**이고 p90 지연이 현행의
1.3배 이내인 후보가 있으면 전환."

| 기준 | 후보1 실측 | 판정 |
|---|---|---|
| 오염 이벤트 ≤ 1/3 | 7/19 = **0.368** | **미충족** (0.333 기준을 간발로 넘김) |
| p90 ≤ 1.3배 | 69.4/141.0 = **0.49배** | 충족 |

다만 게이트가 쓴 "오염 이벤트"는 **재시도를 유발한 횟수**로, 재시도로
복구되면 사용자에게 보이지 않는 **내부 신호**다. 조건 ④가 묻는 것은
"사용자가 받는 답변이 완결되어 있는가"이고, 그 지표는 **표식 수·재시도
소진·잔존 오염**이다:

| 사용자 체감 지표 | 현행 | 후보1 | 비 |
|---|---:|---:|---:|
| 표식(지워진 글자) | 35자 | 3자 | **0.086** |
| 재시도 소진 질의 | 4 | 2 | 0.50 |
| 잔존 오염 질의 | 0 | 1(오탐) | — |

게이트 지표를 사후에 바꿔 통과시키지 않는다 — **문자 그대로는 미충족임을
명시**하고, 의도 기준으로는 큰 폭 충족임을 함께 보고한다. 판단은 사용자
몫이다.

## 5. 전환 시 남는 트레이드오프와 작업

**트레이드오프 — ④는 개선, ⑤는 악화 가능**: 후보1의 실답변은 5건으로
현행 11건의 절반이다(유보표현 19 vs 13). 더 보수적인 것은 ①에 유리하지만,
목회자가 받는 답의 수가 줄어 ⑤(고도의 답)에는 역행할 수 있다. 이 균형은
**신학적·목회적 유용성 판단이라 사용자 채점 영역**이다 — 같은 24건의 두
모델 답변 원문이 JSON에 있으니 비교 채점이 가능하다.

**전환하면 필요한 작업**(이번 변경에 포함되지 않음):
1. `generate_stream()`(UI 주 경로)과 `SermonDraftService`에도 `think=False`
   처리 — 지금은 `generate()`에만 있다. **이것 없이 전환하면 UI 답변이
   빈 문자열이 된다.**
2. `DEFAULT_GEN_MODEL` 변경(`config.yaml::ollama.default_gen_model`).
3. 후보 Modelfile을 임시 태그(`nae-gen-qwen38:ab`)에서 정식 산출물로 승격
   — 저장소에 Modelfile을 커밋하고 재현 가능한 이름을 부여.
4. `_gen_options`의 `num_predict` 재검토(후보 중위 836자, 최대 2,441자).

## 6. 부수 관찰

- **후보1에도 같은 오염 계열이 있다**: `think=False` 확인 호출의 233자
  답변에 `圣灵`(중국어)이 섞였다. 양자화 수준(Q8)이 낮춘 것은 빈도이고,
  결함군 자체가 사라진 것은 아니다. 즉 **모델 교체는 ④의 완화이지 종결이
  아니다.**
- **현행 모델 SYSTEM 프롬프트가 HQ 절대 규칙과 충돌한다**: `my-theology-bot-v2`
  SYSTEM §4가 "설교 대지를 구성할 때는 … 실제적인 **예화**와 적용점을
  균형 있게 제안하세요"라고 지시한다. 그런데 HQ 절대 규칙(2026-09-15)은
  **예화 생성 절대 금지**(자료에 없으면 없는 대로)다. 코드에는
  `_NO_FABRICATED_ILLUSTRATION_DIRECTIVE`가 있지만 모델 SYSTEM은 반대
  방향으로 밀고 있다 — 전환 여부와 별개로 **SYSTEM 프롬프트 §4 수정이
  필요**하다(모든 경로에 영향, 사용자 승인 대상).
- 실행 간 변동: 같은 모델·같은 근거라도 seed를 고정하지 않으므로 오염
  발생 위치·횟수는 실행마다 다르다(J1의 현행 모델 표식 4질의 vs J6 1차
  9질의). **한 실행 안에서의 모델 간 비교**는 유효하고, 실행 간 절대값
  비교는 신뢰하지 않는다.

## 0. 왜 §1 스펙 전체가 아니라 "부분 적용"인가

UX-007 §1은 사이드바를 5개 메뉴로 고정하라고 정의하지만, 그중 2개는
아직 만들어지지 않은 화면에 의존한다:

- **"검색·연구"(Research + Chat 흡수)** — 실제 통합 UI는 §4(검색·연구
  통합) 스펙이고, §4는 아직 구현 안 됨(§15 순서상 이후 단계). 지금
  `Chat` 메뉴 항목을 없애버리면 이미 동작하는 AI 질답 기능이 사이드바
  에서 완전히 사라져 접근할 방법이 없어진다 — 회귀.
- **"설교 연구"(신규)** — §7(설교 연구 허브)이 아직 구현 안 됨. 지금
  메뉴만 만들면 클릭해도 아무 화면도 없는 죽은 링크가 된다.

그래서 이번 iteration은 **의존성이 없는 부분만** 적용한다. §4/§7이
구현되면 그때 `Chat` 단독 항목 제거·"설교 연구" 허브 연결을 별도
Task Order로 마무리한다.

## 1. 작업

**대상 파일**: `ui/app.py::_render_sidebar()` (164~223행). (참고: 과거
`ui/sidebar.py`라는 별도 파일이 있었으나 미사용 죽은 코드로 이미
정리됨 — 착각해서 그 파일을 찾지 말 것)

### 1.1 이모지 전체 제거 (C1-TASK-ORDER-040 §-1 원칙 적용)

`pages` 딕셔너리와 그 아래 렌더링 코드에 있는 모든 emoji를 제거한다:

```python
# 변경 전 (ui/app.py:175-190)
pages = {
    "Dashboard": ("🏠", "홈"),
    "Library": ("🔍", "자료 찾기 · 내 자료"),
    "Processing": ("📄", "자료 등록"),
    "Research": ("🧪", "연구하기"),
    "Chat": ("💬", "AI에게 질문"),
    "설교문 작성": ("📖", "설교 준비"),
    "설교 리뷰": ("🗂️", "설교 모음 정리"),
}
...
pages["도움말"] = ("❓", "내서재 활용 가이드")
```

각 튜플의 첫 번째 값(emoji)을 빈 문자열로 바꾸거나, 아이콘 파라미터
자체를 쓰지 않는 구조라면 튜플을 라벨 문자열 하나로 단순화해도 된다
— 다만 **이 딕셔너리를 소비하는 렌더링 코드(라디오 옵션 생성 부분)도
같이 확인해서 깨지지 않게 할 것**. `### 📊 시스템 상태` 캡션의 emoji도
제거.

### 1.2 라벨 정렬 (UX-007 §1 목표 라벨 중, 기존 화면과 1:1 대응되는 것만)

| 내부 키 | 현재 라벨 | 변경 후 라벨 | 비고 |
|---|---|---|---|
| `Dashboard` | 홈 | 홈 | 변경 없음 |
| `Library` | 자료 찾기 · 내 자료 | **내 자료** | UX-007 §1 목표와 일치 |
| `Research` | 연구하기 | **검색·연구** | 라벨만 변경 — 아직 Chat을 흡수하지 않음(§0 참고), 내부 라우팅 키/렌더 함수는 그대로 `Research`/`render_research_page` |
| `Chat` | AI에게 질문 | AI에게 질문 | **변경 없음, 항목 유지** — §4 구현 전까지 단독 접근 경로 보존 |
| `설교문 작성` | 설교 준비 | 설교 준비 | 변경 없음 — §7 허브 없이는 손대지 않음 |
| `설교 리뷰` | 설교 모음 정리 | 설교 모음 정리 | 변경 없음 |
| `도움말` | 내서재 활용 가이드 | 도움말 | UX-007 §1 목표 라벨과 일치하도록 단순화 |

### 1.3 관리자 전용 섹션으로 이동 (UX-007 §1 명시 사항, 의존성 없음)

- `Processing`("자료 등록")을 일반 사이드바 목록에서 제거하고, 기존
  `Monitor` 게이트 패턴(`NAE_ADMIN_MODE == "1"`)과 **같은 조건으로
  묶어서** 노출한다 — `Monitor`가 이미 이 게이트를 쓰고 있으므로
  (188~189행) 그 옆에 `Processing`도 추가하면 된다.
- 순서: `Processing`, `Monitor` 둘 다 `NAE_ADMIN_MODE=1`일 때만 목록
  하단에 나타나도록. 라벨/내부 키는 변경하지 않는다.
- **주의**: `NAE_ADMIN_MODE` 미설정 환경(일반 베타 테스터)에서는
  `Processing` 화면 자체에 도달할 방법이 없어진다는 뜻이다 — 이건
  UX-007 §1이 의도한 대로다("일반 사용자에게는 불필요"). 이 화면으로
  가는 다른 진입점(예: Dashboard 빠른 시작 버튼의 "문서 추가")이
  있는지 미리 확인하고, 있다면 함께 목록에 적어서 보고서에 남겨라
  (제거하라는 뜻이 아니라 — 사실관계만 기록).

## 2. 하지 않을 것 (범위 밖, 명시적 금지)

- `Chat` 메뉴 항목 제거 또는 `Research`에 병합 — §4 구현 후 별도 Task Order
- "설교 연구" 신규 메뉴 항목 추가 — §7 구현 후 별도 Task Order
- `설교문 작성`/`설교 리뷰` 메뉴 구조 변경
- 라디오 선택 로직(`key="nav_page"`), `_go_to` 콜백 패턴 변경
- `page_renderers` 딕셔너리의 함수 매핑 변경 — 라벨만 바뀌지 내부
  라우팅 키는 그대로
- Core, retrieval, registry 로직 변경
- Dashboard/Library의 §-1 이모지 제거는 이미 TASK-040 이후 반영되어
  있음(현재 코드 확인 후 중복 작업하지 말 것) — 이번 Task는 사이드바
  파일에 한정

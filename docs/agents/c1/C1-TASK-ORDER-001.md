# C1 Task Order 001 — DBMA_CURRENT_STATE_SNAPSHOT.md Legacy 항목 보강

발급: CUE (2026-07-20)
대상: C1 (Cline 작업창 #1, Ollama `dbma-planner-r1-q6:70b`)
검증 근거: 이 명령서의 절차는 오늘 세션에서 실측 검증된 안전 범위(단일
스니펫, OLD/NEW find/replace 스키마)만 사용한다. 이 범위를 벗어나는
어떤 응답도 CUE가 반려한다.

---

## 1. 목적

`docs/agents/c1/DBMA_CURRENT_STATE_SNAPSHOT.md`의 "Entry Point" 절
"Legacy:" 항목이 `dbma.py`라는 파일명만 적혀 있고, 실제로 어디로
이동됐는지(archive 경로)는 빠져 있다. 이 한 줄에 경로 정보만 보강한다.

## 2. 사실관계 (C1에게 그대로 전달할 내용)

```
dbma.py는 2026-07-17 커밋 ce6b05a로 archive/legacy/dbma.py로 이동되어
더 이상 프로젝트 루트에 존재하지 않는다. "Legacy:" 항목 자체는 이미
정확하다(폐기된 파일로 올바르게 분류돼 있음) — 다만 이동된 경로가
빠져 있으므로 그 정보만 추가한다.
```

## 3. C1에게 보낼 프롬프트 (그대로 복사해서 Cline에 붙여넣기)

```text
너는 DBMA 프로젝트의 문서 정합성 검토 보조자다. 아래 사실관계에 어긋나는
줄만 find/replace 스키마(OLD/NEW)로 정정하라. 문서 전체를 다시 쓰지 마라.

사실관계:
dbma.py는 2026-07-17 커밋 ce6b05a로 archive/legacy/dbma.py로 이동되어
더 이상 프로젝트 루트에 존재하지 않는다. "Legacy:" 항목 자체는 이미
정확하다(폐기된 파일로 올바르게 분류돼 있음) — 다만 이동된 경로가
빠져 있으므로 그 정보만 추가한다.

=== 문서 원문 시작 ===
Legacy:

dbma.py
=== 문서 원문 끝 ===

출력은 다음 형식만 사용하라:
OLD: <원문에 실제로 존재하는 정확한 한 줄>
NEW: <교체할 한 줄>
정정이 필요 없으면 "NO_CHANGE"만 출력하라. 이 형식 외의 텍스트(설명,
인사, 전체 재출력)는 절대 출력하지 마라.
```

## 4. 절차

1. 위 §3 프롬프트를 그대로 C1(Cline 창)에 붙여넣는다.
2. C1의 응답을 받는다.
3. **CUE에게 결과를 그대로 전달한다** — C1의 응답을 직접 파일에
   적용하지 않는다. CUE가 아래 §5 검증 절차를 거친 뒤에만 적용한다.

## 5. CUE 사후 검증 절차 (C1 응답을 받은 뒤 CUE가 수행)

- [ ] 응답이 `OLD:`/`NEW:` 또는 `NO_CHANGE` 형식만 사용했는가 (그 외
      텍스트가 섞여 있으면 형식 위반 — 반려)
- [ ] `OLD:` 값이 원문에 실제로 존재하는 줄과 글자 단위로 정확히
      일치하는가 (존재하지 않는 줄을 지목했다면 반려)
- [ ] `NEW:` 값이 사실관계(§2)에서 언급한 내용만 반영했는가 (사실관계에
      없는 내용을 추가/재작성했다면 반려)
- [ ] `dbma.py`라는 단어 자체나 "Legacy:" 분류를 바꾸지 않았는가
      (이 항목은 이미 정확하므로 건드리면 안 됨 — 경로 정보만 추가되어야 함)
- 위 4가지를 모두 통과해야 파일에 적용한다. 하나라도 실패하면 CUE가
  직접 수정하고, 실패 사례는 `feedback_c1_routing_criteria.md`
  shadow 로그에 기록한다.

## 6. 한계 (C1에게 명시적으로 알리고, CUE도 반드시 인지할 것)

- **C1은 이 문서 하나, 이 스니펫(3줄) 하나만 처리한다.** 다른 파일이나
  다른 절을 함께 요청하지 않는다 — 오늘 검증 결과 여러 스니펫을 동시에
  주면 무관한 내용을 삭제/날조하는 실패가 반복 확인됨.
- **C1의 응답은 절대 검증 없이 파일에 바로 적용하지 않는다.** 이
  명령서의 결과물은 반드시 CUE의 §5 절차를 통과해야 한다 — "무검증
  투입 불가" 판정이 아직 유효함([[feedback_c1_routing_criteria]]).
- **C1이 코드(.py)를 작성/수정하는 용도로는 이 명령서를 재사용하지
  않는다.** 이번 작업은 순수 문서(.md) 값 치환이며, 코드 생성은
  오늘 세션에서 검증되지 않은 별개 위험군이다(진단 스크립트 작성 등은
  CUE가 전담하기로 별도 결정됨, [[project_chunking_next_steps]] 참고).
- **C1이 "더 친절하게 설명하고 싶어서" 문장을 늘리거나 새 줄을
  추가하면** — 이는 오늘 세션 내내 반복된 근본 편향이다. 발생 시
  실패로 간주하고 CUE가 직접 처리한다. 이 편향이 다시 나타나는지
  자체도 관찰 포인트로 기록한다.
- 이 작업은 [[feedback_c1_routing_criteria]]의 shadow 카운터(현재
  OLD/NEW 스키마 기준 재시작, 0/10)에 반영되는 실사용 사례 #1이다.

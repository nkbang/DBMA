# C1 Task Order 008 — sermon_corpus 대시보드: 데이터 로드 위젯이 여전히 페이지마다 나오는 버그 재수정

발급: CUE (2026-07-23)
대상: C1 (Cline 작업창 #1)
성격: **버그 재수정 — 지난 작업이 불완전했음.** 코드 변경 범위는
`sermon_corpus/dashboard/web_app.py::main()` 상단 블록 하나로 국한.
이 Task Order 이후 별도로 지시한 대로, **10만 건 확장 계획은 지금
착수하지 않는다** — 이 버그 수정만 먼저 완료할 것.

---

## 1. 배경 — 사용자가 재확인한 문제

지난 지시("데이터 로드 UI를 백그라운드 수집기/데이터 관리 메뉴로 통합하고
매 페이지 헤더에 렌더링되지 않게 하라")에 대해 C1이 `_render_data_load_status()`
(하단 상태 표시 함수)를 `page == "데이터 관리"` 분기 안으로 옮겼다고
보고했으나, 사용자가 실제로 확인해보니 **아직도 페이지마다 "데이터
로드(파일 업로드) 기능"이 나온다**고 재보고했다.

## 2. CUE가 코드로 직접 확인한 원인

`sermon_corpus/dashboard/web_app.py::main()`을 읽어 확인한 결과,
`_render_data_load_status()` 이동은 실제로 반영돼 있었다(이 부분은
제대로 고쳐짐). 그런데 **정작 사용자 눈에 보이는 문제의 원인은 그게
아니었다** — `main()` 최상단, 사이드바에서 `render_sidebar()`로
`page` 값을 받아 분기하기 **훨씬 이전 지점**에 다음 블록이 조건 없이
항상 실행되고 있다(현재 라인 번호 기준 약 1287~1300행):

```python
st.header("📖 DBMA 설교 대시보드")
st.markdown("**설교 본문-제목 데이터셋**의 통계 분석 대시보드입니다.")

# 파일 업로드 섹션
st.markdown("---")
st.subheader("📂 데이터 로드")

file_types = [".jsonl", ".json", ".csv", ".tsv", ".txt", ".xlsx", ".db", ".sqlite", ".sqlite3"]
uploaded_file = st.file_uploader(
    "파일 업로드",
    type=file_types,
    help="JSONL, CSV, XLSX, TXT, SQLite 파일 지원\n중복 데이터는 자동으로 제거됩니다"
)
```

이 블록은 `main()` 함수 진입 직후, `render_sidebar()` 호출(현재 라인
번호 기준 약 1489행 부근, `page` 값을 만드는 지점)보다 **먼저** 실행된다
— 즉 사용자가 사이드바에서 어떤 페이지를 선택하든 이 헤더 3줄 +
업로드 위젯이 항상 화면 상단에 그려진다. 지난 작업은 이 블록을 전혀
건드리지 않았다 — `_render_data_load_status()`(하단 footer)만 옮긴 것과
`st.file_uploader(...)`(상단 위젯) 자체는 서로 다른 코드 위치였는데
이걸 같은 문제로 착각한 것으로 보인다.

## 3. 수정 지시

### 3.1 원칙 — 계산과 표시를 분리 (지난 지시와 동일 원칙 재확인)

- **바뀌면 안 되는 것**: `uploaded_file`을 받아 `records`/`cumulative_records`를
  만드는 **데이터 로드·중복제거·누계 반영 계산 로직**(파일 업로드가
  실제로 들어왔을 때 그걸 처리하는 코드) 자체는 유지한다. 이 계산은
  업로드가 발생했을 때만 실행되면 되고, 모든 페이지가 `analyzer`를
  쓰므로 페이지 분기 전에 결과(`cumulative_records`)가 준비돼 있어야
  하는 것도 맞다 — 이 부분은 지난 설명대로 불가피하다.
- **바뀌어야 하는 것**: 위 §2에 인용한 `st.header`/`st.subheader`/
  `st.file_uploader` — 즉 **사용자에게 보이는 업로드 UI 자체**는 무조건
  렌더링돼서는 안 된다. `page == "데이터 관리"`일 때만 그려야 한다.

### 3.2 구체적 변경

1. `main()` 최상단의 `st.header("📖 DBMA 설교 대시보드")`부터
   `uploaded_file = st.file_uploader(...)`까지의 UI 렌더링 코드를
   그대로 함수(예: `_render_upload_widget() -> Optional[UploadedFile]`)로
   빼낸다. 함수는 `uploaded_file` 객체만 반환하고 화면에는 아무것도
   그리지 않는 모드도 필요하다 — 즉:
   - **호출은 여전히 `main()` 최상단에서 한 번 해야 한다**(업로드된
     파일이 있는지는 페이지 분기 전에 알아야 `records`를 계산할 수
     있으므로) — 단, **위젯을 그릴지 말지는 별도로 결정**해야 한다.
2. Streamlit 위젯은 "그리지 않으면 값도 못 받는다"는 제약이 있으므로,
   다음 중 하나로 해결한다(권장: 방법 A):
   - **방법 A (권장)**: `st.file_uploader`를 사이드바 `render_sidebar()`
     내부로 옮기되, `page == "데이터 관리"`일 때만 실제로 `st.file_uploader(...)`
     를 호출해 렌더링하고, 그 외 페이지에서는 이전에 업로드된 파일을
     세션에 남겨두지 않는 대신 **이미 반영된 `PERSISTENT_DATA_FILE`
     누계 파일을 기준으로 분석하면 되므로 새 업로드 자체가 없어도
     무방**하다. 즉 파일 업로드는 원래도 "데이터 관리" 페이지에서만
     하는 행위이므로, 위젯 자체를 그 페이지 분기 안으로 완전히
     옮기고, 다른 페이지에서는 `uploaded_file = None`으로 처리해도
     기존 동작(누계 파일 기반 분석)과 동일하다.
   - 방법 B: 위젯은 항상 렌더링하되 `st.sidebar`나 `st.expander`로
     접어서 시각적으로 눈에 안 띄게만 한다 — 이건 미봉책이므로 방법 A가
     불가능할 때만 차선으로 고려.
3. 헤더 문구(`st.header("📖 DBMA 설교 대시보드")`, 설명 텍스트)는
   대시보드 타이틀이므로 페이지 상단에 남겨도 되지만, **"📂 데이터
   로드" subheader와 업로드 위젯은 반드시 "데이터 관리" 페이지에서만**
   나오게 한다.

### 3.3 검증 방법

수정 후 각 페이지(개요/본문 빈도/키워드 분석/본문-주제 상관관계/
연도-연대 통계/데이터 테이블)를 순서대로 열어, "📂 데이터 로드"
subheader와 파일 업로드 버튼이 **"데이터 관리" 페이지에서만** 보이고
나머지 페이지에는 전혀 안 보이는지 스크린샷 또는 텍스트로 직접
확인한 뒤 보고하라. "고쳤다"는 보고만으로는 부족하고, 실제로 페이지를
넘겨본 결과를 근거로 제시할 것.

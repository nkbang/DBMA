## 0. §9 원칙 (그대로 인용)

| 상태 | 원칙 |
|---|---|

전체가 대상.

## 1. 오류 메시지 — 원시 예외 노출 제거 (우선순위 1순위, 가장 명확함)

CUE가 grep으로 찾은 위반 지점(출발점일 뿐, 전수 조사는 C1이 직접):

| 파일:라인 | 현재 | 문제 |
|---|---|---|
| `ui/pages/research.py:346` | `f"세션 저장 중 오류 발생: {str(e)}"` | 원시 예외 노출 |
| `ui/pages/research.py:701,703` | `f"에러: ... — {str(e)}"` | 원시 예외 노출(스펙 §4.4가 명시적으로 지목했던 바로 그 위반 지점, 아직 미수정 상태였음) |

**수정 원칙**: 원시 예외 텍스트를 화면에서 지우고, "무엇을 다시 하면
되는지"를 안내하는 문장으로 바꿔라(예: "검색 중 문제가 있었습니다.
다시 시도해주세요." — `chat.py`의 기존 `generate_answer()`가 이미
이 원칙을 따르고 있으니 그 톤을 참고). **원본 예외는 화면에서
지우되 로그에는 남겨라** — 각 파일에 `import logging` +
`logger = logging.getLogger(__name__)`가 없으면 추가하고(이미 있는
파일은 재사용), `logger.exception(...)` 또는 `logger.error(...)`로
기록. `research.py`/`chat.py`는 이미 이번 세션에서 이 패턴을 여러
번 썼다(예: `research.py`의 `generate_answer` 호출부) — 그대로
따라 하면 된다.

## 2. "처리되지 않은 문서" 상태 메시지 (§9 4번째 행)

`ui/pages/library.py:471~478`(`_render_metadata_edit_form`)이 이미
"아직 처리되지 않은 문서입니다"까지는 표시하지만, "자료 등록으로
이동" 버튼이 없다.

**주의(스펙 원문 그대로)**: "관리자 경로 안내는 제외, 일반 사용자에게는
'곧 준비됩니다' 수준으로만" — `Processing`("자료 등록") 페이지는
Task Order 041로 `NAE_ADMIN_MODE=1`일 때만 사이드바에 보인다. 그러므로:
- `NAE_ADMIN_MODE=1`(관리자)일 때만 "자료 등록으로 이동" 버튼을
  보여줘라(클릭 시 `st.session_state["nav_page"] = "Processing"` +
  `st.rerun()`, 기존 `_go_to` 콜백 패턴과 동일).
- 그 외(일반 사용자)에는 버튼 없이 "곧 준비됩니다" 수준 문구만
  유지(현재 문구를 그 톤으로 다듬어도 되고 그대로 둬도 됨 — 버튼만
  추가하지 마라).

다른 화면에도 같은 패턴(등록은 됐지만 아직 처리 안 된 문서를 클릭
가능한 형태로 노출하는 곳)이 있는지 확인하고 있으면 같은 원칙 적용.
없으면 "해당 없음"으로 보고서에 명시.

## 3. 빈 화면 — Dead End 여부 감사

CUE가 찾은 `st.info`/`st.warning` 호출 목록(아래, grep 결과 — 전부
문제라는 뜻이 아니라 검토 대상 목록):

```
library.py:210, dashboard.py:580, monitor.py:307/312/377,
processing.py:347/387/475/480/533/626, research.py:311/498/522/571,
sermon_draft.py:188/310, sermon_review.py:40/87, sermon_research.py:31
```

각각에 대해:
- **이미 다음 행동이 명확한 경우**(예: 검색창 바로 위에 "검색어를
  입력하세요" — 입력창 자체가 다음 행동이므로 버튼 불필요) → 그대로
  둔다, 억지로 버튼 추가하지 마라.
- **성공/완료 상태 안내**(예: "모든 책의 임베딩 커버리지가
  100%입니다") → Dead End 아님, 그대로 둔다.
- **진짜 막다른 화면**(할 일이 없고 다음 행동 버튼도 없는 경우) →
  가장 자연스러운 다음 행동 버튼 1개 추가(예: 목록이 비었으면 "새로
  고침" 또는 관련 화면으로 이동하는 버튼).

**판단 기준을 보고서에 표로 남겨라** — 각 지점을 "버튼 불필요(이유)"
/ "Dead End라 버튼 추가"로 분류.

## 4. 로딩 패턴 — 확인만(수정 예상 안 함)

`processing.py`/`sermon_review.py` 등이 이미 `st.spinner`를 쓰고
있다. 새 로딩 UI를 만든 곳이 있는지만 grep으로 확인하고
(`grep -rn "st.progress\|custom.*loading\|스피너" ui/`), 없으면
"위반 없음"으로 보고서에 명시 — 이 항목 때문에 코드를 새로 만들지
마라.

## 5. 하지 않을 것

- Core/retrieval/registry 로직 — 무변경.
- 이미 좋은 빈 화면에 억지로 버튼 추가 — §3의 "판단 기준" 원칙 지켜라.
- Task Order 040~048에서 이미 다룬 기능(설교 연구, 인용 카드, AI
  답변, 사이드바) — 이번엔 오류 메시지/빈 화면 문구만, 기능 로직은
  건드리지 마라.

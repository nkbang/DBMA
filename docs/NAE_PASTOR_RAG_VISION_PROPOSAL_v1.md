## 1. Executive Summary

이 제안서는 **상용 성경 연구 소프트웨어(Logos 등)가 가진 근본적 한계**를 분석하고, **목회자가 신학적 판단의 완전한 통제권을 갖는 개인 RAG(Retrieval-Augmented Generation) 시스템 NAE(내서재)**를 개발해야 하는 취지를 체계적으로 서술한다.

핵심 주장은 다음과 같다:

> 상용 성경 연구 플랫폼은 "신학적 문지기(Theological Gatekeeper)"가 아니라 "콘텐츠 마켓플레이스(Content Marketplace)"이다. 신학적 기준 없이 수익성에 따라 자료를 선별·진열하며, AI 기능은 신학적 위계를 무시한 채 모든 자료를 동등한 "지식 자원"으로 처리한다.
>
> 따라서 목회자는 자신의 신학 전통, 신앙고백, 목회적 판단이 반영된 **검증된 자료만 포함하는 개인 RAG 인덱스**를 구축하고, 이를 AI 시대의 신학 도구 표준으로 삼아야 한다.

NAE는 이 비전을 실현하기 위해 설계된 **개인 목회자 전용 지식 관리 및 AI 연구 시스템**이다. Logos를 "만물상(萬物商)"으로 활용하되, 신학적 권위와 최종 판단권은 목회자가 갖는 구조를 지향한다.

## 2. 문제 정의

### 2.1 상용 성경 연구 플랫폼의 신학적 무규제성

Logos Bible Software(Faithlife)를 비롯한 주요 상용 성경 연구 플랫폼은 다음과 같은 근본적 한계를 가진다:

| 구분 | 신학교/교단/출판사 (전통적 권위) | Logos/Faithlife (플랫폼 기업) |
|------|------|------|
| **선별 기준** | 신앙고백(Confession), 정통성(Orthodoxy), 이단 판정 | 수요(Demand), 저작권 확보 가능성, 마진율 |
| **레귤레이션** | 내교리 헌법, 이단대책위원회, 신학적 심의 | 없음 (단, 법률적 저작권/명예훼손 외) |
| **LDS 자료 판매 이유** | "이단 연구용"이라며 제한적 허용 | "팔리니까(수요 있으니까) 판다." |
| **통일교/불교/이슬람 자료** | 신학적 금기로 배제 | 수요 생기면 즉시 상품화 가능 |

**핵심 문제:** 플랫폼은 다음 질문에 대해 명확한 신학적 답을 제공하지 않는다.

- 무엇이 정경(Canon)인가?
- 무엇이 정통 교리인가?
- 무엇이 이단인가?
- 어떤 자료는 목회적 교육에 부적절한가?
- 어떤 자료는 비판적 연구라는 제한된 맥락에서만 다루어져야 하는가?

플랫폼은 이 모든 판단을 사용자에게 넘기며, 이는 상업 플랫폼의 언어로 바꾸면 **"가능한 넓은 카탈로그를 제공하고, 선택의 책임은 구매자에게 맡긴다"**는 뜻이 된다.

### 2.2 "만물상" 플랫폼의 본질

Logos는 신학적 권위기관이 아니라 **종교 텍스트를 유통하는 만물상(萬物商)**이다.

```
로고스 진열대                    목회자의 태도
─────────────                    ─────────────
정통 신학 (개혁파, 장로교...)   → 핵심 재고 (大量 구매·상시 비치·주력 활용)
가톨릭/정교회/성공회 자료        → 참고 재고 (교부신학, 교회사 연구 시 선별)
이단 자료 (몰몬, JW, 안식교...)  → 대응용 샘플 ('연구용' 딱지, 금고 보관)
세계종교 (이슬람, 불교...)       → 전도/변증용 참고서 (필요 시 대여 수준)
자유주의/비평학/세속 학문        → 독소 포함 재고 (해독제 갖춘 자만 취급)
```

**만물상 생존법 3원칙:**

1. **눈속임 당하지 마라** — 진열대 배열이 '추천'이 아님을 알 것
2. **내 창고에 들일 기준은 내가 정한다** — 로고스 추천 알고리즘이 기준 아님
3. **쌀과 겨를 같은 자루에 담지 말라** — 컬렉션·태그·검색범위로 물리적 격리 필수

### 2.3 Logos의 구체적 사례: LDS 분류의 전략적 모호성

로고스는 공식 문서에서 LDS(말일성도)를 다음과 같이 이중적으로 처리한다:

| 층위 | 실제 태도 | 문제점 |
|------|-----------|--------|
| **공식 가이드** | "Denominational Libraries" 예시에 LDS를 장로교·침례교와 나란히 배치 | "정통 기독교 아님" 한 줄 병기 → 모순 |
| **실제 상품** | LDS 전용 베이스 패키지 없음 → "Mormon Studies Collection"(연구용)으로만 판매 | 교단 라이브러리 메뉴에 진열해 놓은 것과 충돌 |
| **신학적 입장** | "정통 기독교 교회로 간주되지 않는 그룹"이라고 명시 | 마케팅과 신학 입장이 정면 충돌 |



## 3. Logos 사례 분석: "만물상" 플랫폼의 본질

### 3.1 Logos의 실제 구조

| 층위 | Logos의 실제 역할 | 목회적 의미 |
|------|-------------------|-------------|
| **성경 연구 도구** | 원어, 형태론, 주석, 성경 상호참조, 설교 준비 | 매우 유익한 연구 인프라 |
| **디지털 도서관** | 다수 출판사의 신학·교회·종교 텍스트 판매 | 도서 유통 및 락인 플랫폼 |
| **데이터 플랫폼** | 책을 태깅·상호연결·검색 가능한 데이터로 변환 | 텍스트가 "신학"보다 "검색 단위"가 되기 쉬움 |
| **AI 플랫폼** | 자연어 검색, 요약, Bible Study Builder 등 | 자료 간 위계와 경계가 AI 응답에서 흐려질 위험 |

### 3.2 Logos는 "신학적 문지기"가 아니다

로고스에 없는 유일한 '레귤레이션': **"돈이 되는가?"**

```
장로교 신조 (Westminster Standards) = 상품 (잘 팔림)
몰몬경 (Book of Mormon)           = 상품 (잘 팔림 → 연구용 명분 붙여 판매)
코란 (Quran)                      = 상품 (팔림)
원리강론 (Divine Principle)        = 아직 상품화 안 됨 (수요/저작권 계산 안 서서)
신천지 교리책 (계시록 실상 등)     = 수요 생기면 즉시 상품화 가능
```

**로고스 프레임 안에는 '정경(Canon)'이 없다. 오직 '카탈로그(Catalog)'만 있을 뿐이다.**

### 3.3 사모펀드 소유의 영리 기업

- **소유 구조:** 2021년 사모펀드 Cove Hill Partners가 Faithlife(로고스 모회사) 인수
- **수익 모델:** 연간 $99~$799+ 티어별 구독료 + 라이브러리 업그레이드·개별 도서 상시 할인
- **채용 공고:** "Sales Operations Specialist", "Growth Insights Analyst" — 신앙고백·교회 추천서 요구 없음
- **비판적 시각:** "Logos is not a Christian company. It's a secular private-equity-backed software company that sells Christian content."

## 4. AI 시대의 신학 도구 위기

### 4.1 AI는 "진리의 도구"보다 "정보 변환기"다

AI 기업은 대개 자료의 진리성보다 다음을 우선한다:

1. 데이터 접근 가능 여부
2. 저작권·라이선스 계약
3. 사용자의 구독 유지율
4. 질문당 응답 품질과 속도
5. 개인화와 추천 성능
6. 콘텐츠 판매 전환율

**AI는 "이 자료가 교회적으로 안전한가?"보다 "이 자료가 질문에 언어적으로 관련 있는가?"를 먼저 판단한다.**

### 4.2 구독제가 신학 도구를 서비스화한다

```
과거: "내가 필요한 책과 기능을 사서 오래 쓴다."
현재: "내 연구 환경 전체를 계속 구독한다."
미래: "내가 보유한 라이브러리, AI 연구 보조, 설교 워크플로, 클라우드 노트, 
       공동 작업 환경이 하나의 서비스에 묶인다."
```

결과적으로 플랫폼은 단순한 도구가 아니라 **연구 습관과 목회 준비 과정의 운영체제(OS)**가 된다. 이때 사용자의 신학적 자율성은 책의 선택뿐 아니라 검색 기본값, AI 참조 범위, 추천 알고리즘, 구독 티어에 의해 영향을 받는다.

### 4.3 출판사는 데이터 공급자가 된다

```
과거: 출판사 → 책을 출판
현재: 출판사 → 검색 가능한 본문, 태그, 인물·장소·주제 데이터, 
       AI 요약과 질의응답의 근거 데이터, 추천 엔진의 입력값을 공급
```

이 구조에서 책은 더 이상 단지 "저자의 논증"이 아니라 **"AI가 재조합할 수 있는 데이터 자산"**이 된다.

### 4.4 AI 시대의 구체적 위험

과거 Logos에서는 사용자가 LDS 자료를 구매하고 열어야 했다. 그러나 **AI 기능이 활성화될수록** 사용자가 의도하지 않았더라도, 라이브러리에 들어온 다양한 전통의 자료가 답변의 근거 후보가 될 수 있다.

**예시:** 사용자가 "삼위일체의 성경적 근거를 설명하라"고 물었을 때, 목회자가 기대하는 것은 성경 본문, 정통 신조, 건전한 주석과 조직신학의 질서이다. 그러나 플랫폼이 폭넓은 종교 자료를 같은 "지식 자원"처럼 처리한다면, 사용자는 어느 자료가 정통 교회의 고백인지, 어느 자료가 반대 견해를 소개하는지, 어느 자료가 비판 연구의 대상인지 스스로 판별해야 한다.

## 5. NAE 비전: 목회자가 주인인 개인 RAG 시스템

### 5.1 미래 기독교 산업의 세 갈래

| 유형 | 특징 | 장점 | 위험 |
|------|------|------|------|
| **광범위 플랫폼형** | 여러 교단·종교·학문 자료를 폭넓게 유통 | 자료 접근성과 연구 효율 | 교리적 경계가 흐려짐 |
| **교단·신학교 큐레이션형** | 신앙고백과 교육 기준으로 자료 선정 | 신학적 안전성과 교육 일관성 | 자료 폭과 기능이 제한될 수 있음 |
| **개인 RAG형** | 목회자·교회가 직접 검증한 자료만 AI에 넣음 | 가장 높은 통제력과 맞춤성 | 구축·관리 비용과 기술 역량 필요 |

**NAE는 세 번째 길 — 개인 RAG형 —을 지향한다.**

### 5.2 NAE의 핵심 철학

```
Logos = 만물상 (도매상)
NAE   = 곳간 (내 서재, 내 신학, 내 양떼를 지키는 금고)
```

| 원칙 | 실행 지침 |
|------|-----------|
| **신학적 권위는 목회자에게 있다** | AI의 최종 판단권은 절대 플랫폼에 맡기지 않는다 |
| **검증된 자료만 인덱스에** | 신앙고백, 정경, 검증된 주석, 교단 자료만 포함 |
| **물리적·논리적 격리** | 이단·타종교 자료는 별도 컬렉션, 기본 검색에서 제외 |
| **소유 vs 구독** | 영구 라이선스 중심, 구독은 서비스 기능에만 한정 |
| **오픈 표준** | 벤더 락인 방지, 데이터는 목회자의 것 |

## 6. 핵심 설계 원칙

### 6.1 신학적 큐레이션 (Theological Curation)

NAE의 가장 핵심적인 기능은 **목회자가 자신의 신앙고백과 신학 전통에 따라 자료를 선별·격리·위계화**하는 것이다.

| 기능 | 설명 |
|------|------|
| **신학 전통 프로필** | 개혁파, 침례교, 루터교, 감리교 등 선택 → 기본 검색 범위 자동 설정 |
| **자료 격리** | 이단·타종교·자유주의 자료는 별도 컬렉션, 기본 검색에서 제외 |
| **위계 부여** | 정경 > 신조 > 주석 > 신학서적 > 참고자료 — AI 응답 시 이 순서 우선 |
| **인용 출처 확인** | AI 응답의 모든 인용은 원문 출처와 함께 표시, 위조·오인용 방지 |

### 6.2 개인 지식 관리 (Personal Knowledge Management)

| 기능 | 설명 |
|------|------|
| **설교 지식 그래프** | Obsidian 연동, 설교·연구 노트의 개념 간 연결 시각화 |
| **개인 아카이브** | PDF, 논문, 한국어 자료, 개인 문서의 장기 보관·OCR·분류 |
| **태그·메타데이터** | 신학적 분류 체계에 맞춘 사용자 정의 태그 시스템 |
| **데이터 소유** | 모든 데이터는 목회자의 로컬 저장소에 우선 저장, 클라우드 동기화 선택 |

### 6.3 통제된 AI (Controlled AI)

| 기능 | 설명 |
|------|------|
| **RAG 인덱스 분리** | 검증된 자료만 포함하는 별도 인덱스, 외부 플랫폼 자료는 참조 불가 |
| **AI 참조 범위 제한** | "이단 연구용" 컬렉션은 설교 답변에 절대 참조되지 않도록 기술적 차단 |
| **인간 검토 게이트** | 설교 원고의 AI 생성 내용은 반드시 인간 검토 후 사용 |
| **로컬 LLM 우선** | 개인정보 보호를 위해 가능한 한 로컬 모델 사용, 클라우드 API 선택 |

### 6.4 상호운용성 (Interoperability)

| 원칙 | 실행 |
|------|------|
| **벤더 중립** | Logos, Devonthink, Obsidian 등 타 도구와 데이터 교환 가능 |
| **오픈 포맷** | Markdown, JSON, PDF 등 개방형 표준 포맷 우선 |
| **데이터 이식성** | 언제든지 다른 플랫폼으로 마이그레이션 가능 |
| **API 공개** | 목회자가 자신의 데이터를 프로그래밍적으로 접근·처리 가능 |

## 9. 결론

### 9.1 핵심 메시지

> **"Logos에는 자료를 두되, Logos의 분류와 AI의 추천에는 신학적 판단권을 맡기지 말라."**

NAE는 이 메시지를 기술적으로 구현하는 시스템이다. Logos를 "만물상"으로 활용하되, **신학적 권위와 최종 판단권은 목회자가 갖는 구조**를 지향한다.

### 9.2 NAE가 해결하는 근본 질문

| 질문 | Logos의 답 | NAE의 답 |
|------|-----------|----------|
| **무엇이 정경인가?** | 플랫폼이 정의 (카탈로그 기준) | 목회자가 정의 (신앙고백 기준) |
| **어떤 자료가 안전한가?** | 검색 가능성 기준 | 신학적 검증 기준 |
| **AI가 답할 때 누가 판단하는가?** | 알고리즘이 우선 추천 | 목회자가 최종 검토 |
| **데이터는 누구의 것인가?** | 플랫폼이 관리 | 목회자가 완전 소유 |

### 9.3 다음 단계

1. **HQ 승인:** 본 제안서의 취지 및 방향성 승인
2. **SPRINT 계획:** Phase 1~4의 구체적 스프린트 계획 수립
3. **PoC 구현:** 핵심 RAG 엔진 프로토타입 개발
4. **목회자 테스트:** 실제 목회 워크플로 검증
5. **점진적 확장:** 기능 추가 및 최적화

# PM 제품 의도 정렬 및 배포 준비 점검

## 0. 한 문단 결론

현재 앱은 **"검증 가능한 답변"을 만드는 부품은 거의 다 갖췄으나, 그 부품들이
목회자가 실제로 답을 받는 경로에 연결되어 있지 않다.** 신뢰 등급(TrustTier),
의미 경계 청킹, 교단 어휘 필터, 근거 판정기(groundedness judge)가 모두 코드로
존재하지만 각각 상수 고정·dormant·설교 경로 전용 상태다. 그 결과 제품이 약속한
"신뢰 기반"은 현재 **모델 프롬프트 한 겹**에 의존하고 있으며, 그 프롬프트조차
브랜치에 고립되어 통합 대상 브랜치에 들어가 있지 않다. 배포 판단은 **조건부
보류**다(§8).

## 1. 현재 구조 (실측 기준)

### 1-1. 답변 경로 (목회자가 실제로 쓰는 경로)

```text
질의 (ui/pages/chat.py)
 → QueryProcessor (core/retrieval.py)
     · QueryParser: intent / themes / keywords / 장절참조
     · 하이브리드 랭킹 = 0.25×BM25 + 0.20×vector + 0.30×theological
                        + 0.20×PassageMatch + 0.05×SourceTierBonus
       × (0.9+0.1×evidence_confidence) × content_quality_factor(0.7~1.0)
     · CitationBuilder → Citation(저자·서명·위치·발췌 200자)
 → ContextAssembler → llm_context_block  ← 서지 정보 없음 (§3 위험 R3)
 → GenerationService.generate_stream (core/generation.py)
     · 프롬프트 = [대화이력] + 자료블록 + 질문
     · CJK/태국어 오염 탐지 → 2회 재시도 → 최종 문자 삭제
 → ClaimGuard 사후 탐지 → UI 경고 배너 (답변 자체는 수정하지 않음)
 → 인용 카드 (ui/components/citation_card.py, "원문 다시 보기" 버튼)
```

병렬로 사전류(Smith) 보조 검색이 `NAE/reference_retrieval_adapter.py`를 통해
문맥에 주입된다(fault-isolated).

### 1-4. 미병합 상태 (일정에 직접 영향)

2026-09-10 품질 수정 3건이 `claude/theological-pastoral-response-quality-89b049`
(`861ebdf`)에 있고, 문단 답변 설계가 `claude/jovial-lovelace-31c137`(PR #10)에
있다. **둘 다 `dev/dbma-engine`·`main` 어디에도 병합되지 않았다.** 즉 지금
빌드해서 배포하면 근거 강제 지시문·한국어 QueryParser·교단 지시문·200자 절단
제거가 **전부 빠진 채로** 나간다.

## 3. 문제 및 위험

| ID | 위험 | 심각도 | 설명 |
|---|---|---|---|
| R1 | **품질 수정 고립** | 치명 | §1-4. 배포 빌드에 근거 강제·한국어 랭킹이 빠진다 |
| R2 | **신뢰 등급 상수 고정** | 높음 | 검색 결과 전량 T1 → ClaimGuard의 "T1 근거 없으면 차단" 규칙이 **구조적으로 발화 불가**. 안전장치가 있는 것처럼 보이지만 항상 통과. 실제 후보는 19세기 주석(T3 성격)이라 라벨 자체가 부정확 |
| R3 | **LLM이 서지 정보를 못 받음** | 높음 | 문맥 블록이 `<context id="TSU-..." score="...">`뿐. 모델이 본문에서 "풀러는 …라고 말한다"라고 쓸 수 없어, 출처 표기가 카드 목록에만 남는다 |
| R4 | **문장 조각 근거** | 높음 | 평균 204자 문장 단위 근거 → 신학 논증의 전제·양보절이 잘려 의미 왜곡 가능 |
| R5 | **지시문 준수 미측정** | 높음 | 근거 강제·교단 관점 지시문이 실제로 지켜지는지 측정 계층이 chat 경로에 없음 |
| R6 | **환각 탐지 부재** | 높음 | R8 항목과 동일 — 절대 표현이 없는 그럴듯한 창작은 무경고 통과 |
| R7 | **언어 손상형 방어** | 중간 | 오염 문자 삭제가 "완결 문장" 요구와 정면 충돌 |
| R8 | **TSU `claim` 필드 오용 가능성** | 중간(잠재) | LLM 생성 한국어 요약. 검색·인용 대상에 넣자는 제안이 오면 "AI 생성물을 근거로 인용"이 된다 |
| R9 | **사람 검토 0건** | 중간 | 코퍼스 전량 `review_status=generated`. "검증된 자료"라는 표현은 현재 근거가 없다 |
| R10 | **문서-코드 괴리** | 중간 | `docs/STATE.md`가 자체적으로 "장기간 갱신 누락" 3회를 기록. 배포 판단을 문서에 의존하기 어렵다 |

## 5. 개선안

### 5-1. 배포 전 최소 세트 (권고)

**전제 판단: 청킹 전면 재설계를 배포 전에서 배포 후로 미룰 수 있게 하는
지렛대는 이미 설계돼 있다.** `docs/NAE_PARAGRAPH_ANSWER_DELIVERY_DESIGN_v1.md`
의 **옵션 A(문단 앵커드 근거)** — 검색 단위는 TSU(문장) 그대로 두고, 답변
조립 시점에 각 히트를 `canonical.json`의 **원문 문단 전체**로 확장한다.
재임베딩·재색인·`builder_version` 변경이 없고, ADR-030 frozen baseline과
ADR-001(RetrievalEngine 무수정)을 건드리지 않는다. R4를 해소하면서
ADR-007/008(Proposed) 확정을 기다리지 않아도 된다.

| 순서 | 과제 | 해소 위험 | 성격 |
|---|---|---|---|
| P0-1 | 미병합 3커밋을 `dev/dbma-engine`에 통합 | R1 | 병합·회귀 |
| P0-2 | 옵션 A 구현 (문단 앵커드 근거) | R4 | 구현 |
| P0-3 | 문맥 블록에 서지 정보 주입 (저자·서명·위치) | R3 | 소규모 구현 |
| P0-4 | TrustTier 상수 고정 해소 — 실제 dataset의 tier를 payload에서 읽거나, 읽을 수 없으면 **T1로 위장하지 말고 미상으로 표기** | R2 | 소규모 구현 + 판단 |
| P0-5 | 대표 질의 세트(본문주해·교리·설교적용·논쟁·상담·한영혼합·근거부족 7종) 구축 후 **사람 채점** | R5·R6 | 평가 |
| P0-6 | 근거 부족 시 유보 응답 — 검색 결과 0건/저점수 임계 미만이면 생성 대신 "등록된 자료에서 확인되지 않음" 반환 | R6 | 소규모 구현 |

P0-4·P0-6은 새 모델·새 알고리즘을 도입하지 않는다. **신뢰 안 된 분류기 위에
처리 경로를 얹지 않는다**는 기존 원칙에 맞춰, 판정을 추가하는 대신 **거짓
신호를 제거**하는 방향이다.

### 5-2. 배포 직후 우선

- groundedness 판정을 chat 경로에 연결 (ADR-010 Phase 2) — R5의 자동 측정
- 주장 단위 인용 앵커 (문단→인용 ID 매핑)
- 신학 프로필 저장 모델 + 최소 설정 화면 (교단/신앙고백/선호저자/제외입장)
- `_sermon_usability_score()` `academic_terms` 한국어화 (SUS 가중치 0.20)
- THEME_KEYWORDS에 조직신학 주제(칭의·성화 등) 추가
- 시나리오별 출력 형식을 chat/research로 확장

### 5-3. 장기 고도화

- ADR-007/008 확정 후 의미 경계 청킹 프로덕션 전환 (dormant 모듈 배선)
- 다단계 생성 파이프라인(근거수집 → 정합성 검증 → 초안 → 인용 검증 → 문체 다듬기)
- 다중 관점 비교 모드 / 교단 정책 팩
- 코퍼스 사람 검토 워크플로 실집행 (R9)

## 7. 일정·의존성·완료 기준

작업량은 **세션 단위**로 표기한다(1세션 ≈ 집중 작업 반나절). 담당은 CUE 구현 /
C1 보조 / 사용자(Rev. Bang) 판단으로 나눈다.

| 과제 | 규모 | 의존성 | 담당 | 완료 기준 |
|---|---|---|---|---|
| P0-1 병합 | 1 | base 최신 확인 선행 | CUE | `dev/dbma-engine`에서 회귀 GREEN, 중복 재구현 없음 |
| P0-2 옵션 A | 2~3 | PR #10 Task Order 승인 | CUE | 인용 카드·LLM 문맥이 원문 문단 전체를 받음, 재색인 0 |
| P0-3 서지 주입 | 1 | ADR-024 §C 영향 확인 | CUE | 문맥 블록에 저자·서명·위치 포함, 모델 답변에 출처 문장 출현 확인 |
| P0-4 TrustTier | 1 | ClaimGuard 규칙 영향 확인 | CUE | 위장 T1 제거, ClaimGuard 규칙이 실제 분포로 판정 |
| P0-5 질의 세트 | 2 + 채점 | P0-1~P0-4 완료 후 | CUE 구축 / **사용자 채점** | 7유형 각 3문항, 인용정확·신학정합·문맥보존·언어품질·활용가능 5축 채점 |
| P0-6 유보 응답 | 1 | 임계값 결정 | CUE + 사용자 판단 | 근거 부족 질의에서 창작 대신 유보 문구 반환 |

**차단 요인**: P0-5의 채점은 사용자만 할 수 있다. 배포 일정의 임계 경로는
구현이 아니라 **이 인적 평가**다.

**ADR 처리**: ADR-009 Amendment A는 **Proposed**다. 승격 4조건(구현 완료·회귀
통과·C1 리뷰·사용자 승인) 중 앞의 둘만 충족했다. P0-5 완료 시점에 C1 리뷰와
승인을 함께 처리하는 것을 권고한다. ADR-007/008은 배포 전 손대지 않는다.

## 8. 배포 판단

### 배포 가능한 범위 (현 상태 + P0 완료 시)

- 개인 서재 문서 등록·정리·읽기
- 등록 자료 기반 검색과 인용 카드 제시
- 설교 초안 작성 보조 (교단 어휘 필터가 이미 연결된 유일한 경로)
- **단일 사용자(Rev. Bang) 전용 전제**

### 배포를 보류해야 할 요소

1. **P0 미완 상태의 배포는 권고하지 않는다.** 특히 R1(고립)과 R2(위장 T1)는
   "안전장치가 있다"는 인상을 주면서 실제로는 작동하지 않는 형태이므로,
   기능 부재보다 위험하다.
2. **"검증된 자료"라는 제품 표현은 현재 사실이 아니다** — 코퍼스 사람 검토
   0건(R9). 배포 문구는 "등록·처리된 자료"로 조정할 것을 권고한다.
3. **다중 사용자·교단 선택 기능을 광고하지 말 것.** 프로필 계층이 없다.
4. ADR-030 frozen baseline(3,319 / 34,948)은 배포 전 재처리 대상이 아니다.

### PM 권고 (한 줄)

**P0 6항목을 이번 릴리스 범위로 고정하고, 그 외 모든 기능 제안을 배포 후
백로그로 옮긴다. 임계 경로는 P0-5의 인적 채점이므로 지금 착수한다.**

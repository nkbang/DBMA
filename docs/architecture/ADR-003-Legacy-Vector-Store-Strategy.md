## Context

DBMA v1 개발 과정에서 서로 다른 파이프라인이 각각 별도의 vector store를 생성했다.

```
DBMA v1 development period created multiple vector stores:

1. Chroma dbmar_docs      (dbma.py 레거시 인라인 RAG가 생성)
2. Qdrant dbma_sermon     (dbma.py 레거시 인라인 RAG가 생성)
3. TSU dataset            (scripts/build_tsu_dataset.py가 생성, 영구 vector 저장 없음)

These stores contain overlapping corpus data
generated by different pipelines.
```

CUE-20H-2/H-3(Chroma/Qdrant Preservation & Parity Audit)에서 확인한 사실:

- Chroma `dbmar_docs`(6,710 vectors)와 Qdrant `dbma_sermon`(10,570 points) 모두 **TSU/registry와 정확히 동일한 12개 원본 문서**를 커버한다 — 셋 다 같은 corpus의 병행 색인이며, 청킹 전략만 서로 다르다(dbma.py 자체 청커 vs `core/chunking_optimizer.py`).
- `core/retrieval.py::RetrievalEngine`은 Qdrant와 Chroma 어느 쪽도 쿼리하지 않는다(`self.qdrant_url`이 저장만 되고 참조되지 않음, SPRINT20-H-3 코드 검증) — ADR-001의 "RetrievalEngine=Qdrant authority" 전제는 정정되었다(ADR-001 Correction 섹션 참고).
- Chroma는 구버전 스키마(6,515건)와 신버전 스키마(195건, "12. 고린도후서" 1개 문서만) 혼재 — 2026-07-15 커밋(`bf30e8b`, `b6890d3`)이 시작한 metadata migration이 12개 문서 중 1개만 마치고 중단된 것으로 추정된다. Qdrant는 구버전 스키마만 갖고 있어 이 migration이 아예 반영되지 않았다.
- 두 저장소 모두 이번 조사 중 checksum 검증 백업이 완료되었다(Chroma는 sqlite3 직접 조회로, Qdrant는 실제 restore까지 수행하여 검증).

---

## Decision

### Production Authority

```
Production Retrieval Authority:

    core/retrieval.py::RetrievalEngine

Current mechanism:

    TSU dataset (output/bench/tsu_dataset.jsonl)
        +
    core/embedder.py (BGE-M3 via Ollama, MiniLM 폴백)
        +
    in-memory similarity retrieval (cosine, TF-IDF fallback)
```

이 결정은 ADR-001의 Decision(`RetrievalEngine`을 유일한 Retrieval Engine Authority로 지정)을 재확인하며, 그 구현 메커니즘(영구 vector store 미사용)을 명시적으로 기록한다.

### Legacy Stores

#### Chroma `dbmar_docs`

```
Status: Preserved Legacy Artifact

Decision: KEEP

Reason:
- active corpus history (TSU와 동일한 12개 원본 문서를 담고 있음 — 단순 폐기 데이터 아님)
- metadata migration incomplete (12개 문서 중 1개만 신버전 스키마 적용, 나머지 11개는 미적용)
- backup verified (backups/chroma_backup_20260716_233708/, SHA256 checksum 일치)
```

#### Qdrant `dbma_sermon`

```
Status: Preserved Legacy Artifact

Decision: KEEP

Reason:
- active corpus history (TSU/Chroma와 동일한 12개 원본 문서를 담고 있음)
- snapshot verified (backups/qdrant_snapshot_20260717/, Qdrant 자체 API checksum 일치)
- restore tested (별도 테스트 컬렉션에 실제 업로드하여 points_count 10,570 일치 확인)
```

---

## Consequences

- `dbma.py`와 그 인라인 RAG 함수군(`query_rag`, `build_rag_store`, `query_qdrant`, `upsert_to_qdrant`, `embed_text_ollama`)의 archive/제거를 진행하더라도, **Chroma/Qdrant 데이터 자체는 남긴다** — 코드 삭제와 데이터 보존은 분리된 결정이다.
- `chroma_db/`(로컬 디렉토리)와 Qdrant `dbma_sermon` 컬렉션(Docker volume `dbma_qdrant_storage`)은 당분간 디스크에 그대로 유지한다. 별도 archive 위치(예: `archive/legacy_vector_store/`)로의 이동 여부는 CUE-20H-5 이후 별도 결정.
- 두 저장소의 미완성 metadata migration(Chroma 1/12, Qdrant 0/12)은 **완결하지 않는다** — production authority가 TSU 기반으로 확정되었으므로 이 migration을 마칠 이유가 없다. 완성이 아니라 "동결(freeze)" 상태로 문서화한다.

---

## Migration Policy

```
No production dependency may be added to Chroma/Qdrant
without new ADR approval.

Future migration may use these stores only as historical source.
```

- 향후 어떤 코드도 `core/retrieval.py::RetrievalEngine`의 검색 경로에 Chroma/Qdrant 쿼리를 추가해서는 안 된다. 그런 변경이 필요하다고 판단되면 이 ADR을 개정하는 신규 ADR을 먼저 작성한다.
- Chroma/Qdrant는 오직 "과거 데이터 소스"로만 참조 가능하다 — 예를 들어 TSU corpus에 없는 과거 청킹 결과를 감사(audit)하거나 비교 연구에 활용하는 용도. Production 쿼리 경로에 재도입하는 것은 금지한다.

## Finalization (SPRINT20-I-D-7, 2026-07-17)

DBMA v1.1.0 Architecture Consolidation Release에서 legacy code archive가
완료되어(commit `ce6b05a`) 본 ADR을 최종 확정한다.

### Legacy Code Archive 완료

- `dbma.py` 및 Chroma/Qdrant island(`core/search.py`, `core/ingest.py`,
  `core/qdrant_init.py`)이 `archive/legacy/`로 이동 완료(git rename, 삭제 아님).
- 공식 runtime의 archived 모듈 importer 0 확인. `scripts/backup_chroma.py`는
  archived 모듈 import를 제거하고 legacy Chroma 경로를 자체 상수로 선언.

### Legacy Boundary 최종 확정

```
Official Runtime:
    data/RAW                          (원본 문서)
    data/제련완성본                    (처리 산출물)
    data/제련완성본/registry           (Identity Registry, SoT)
    output/bench/tsu_dataset.jsonl     (TSU Dataset)
    cache/embeddings                   (Embedding Cache)
    core/retrieval.py::RetrievalEngine (Retrieval Runtime)

Legacy Storage:
    archive/legacy                     (archived code)
    chroma_db                          (legacy vector store)
    backups                            (legacy snapshots)
```

### Vector Storage 결정 (확정)

- **chroma_db/ → KEEP 확정.** production retrieval dependency 없음(chroma-free
  재확인). 소비자는 dashboard status(`runtime_state._check_vector_index`,
  읽기전용) + legacy recovery 목적뿐. 별도 archive 위치로의 이동은 하지
  않는다(현 위치 유지) — Consequences의 "이동 여부 별도 결정" 항목을 이로써 종결.
- **backups/ → KEEP 확정.** 유효 snapshot 보존(chroma×2, qdrant×1).

### Scope 제외 항목 (ADR-003 대상 아님)

아래는 legacy vector store 정책과 무관한 잔재이며, 별도 cleanup 후보다:

- `data/rag_index/` — 실제 index 파일 없음, `.DS_Store` 잔재뿐.
- `backups/chroma_backup_20260715_203507` — 0B 빈 디렉토리.

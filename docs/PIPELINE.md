# DBMA Pipeline

## 목적
이 문서는 DBMA의 실제 처리 흐름을 단계별로 정리한 파이프라인 문서다.
문서가 들어와서 처리되고, 저장되고, 검색되고, 검증되는 전 과정을 기록한다.

---

## 파이프라인 개요

```text
입력
→ 추출
→ 정제
→ 청킹
→ 저장
→ 임베딩
→ 검색
→ 생성
→ 평가
→ 문서화
```

---

## 1단계: 입력

### 역할
사용자가 문서를 선택하거나 업로드한다.

### 관련 파일
- `dbma.py`
- `ui/tabs.py`

### 주요 작업
- 파일 선택
- 폴더 스캔
- 처리 대상 확인
- 상태 표시

---

## 2단계: 추출

### 역할
문서에서 텍스트를 추출한다.

### 관련 파일
- `core/extractors.py`
- `core/processing.py`

### 주요 작업
- PDF 추출
- DOCX 추출
- EPUB 추출
- HTML 추출
- OCR 필요 시 보조 처리

### 출력
- 원문 텍스트
- 추출 메타데이터
- 오류 로그

---

## 3단계: 정제

### 역할
추출된 텍스트를 읽기 좋게 정리한다.

### 관련 파일
- `core/processing.py`
- `core/utils.py`

### 주요 작업
- 줄바꿈 정리
- 중복 제거
- 노이즈 제거
- 언어 감지
- 품질 점검

### 출력
- 정제된 텍스트
- 품질 점수
- 언어 정보

---

## 4단계: 청킹

### 역할
긴 텍스트를 검색 가능한 단위로 나눈다.

### 관련 파일
- `core/chunking_optimizer.py`
- `core/processing.py`

### 기본값
- chunk size: `1200`
- overlap: `200`

### 주요 작업
- 최적 청킹 시도
- 필요 시 파일별 파라미터 조정
- 청크 품질 검토
- 결과 저장

### 출력
- 청크 목록
- 청크 메타데이터
- 청킹 로그

---

## 5단계: 저장

### 역할
처리 결과를 md와 보조 파일로 저장한다.

### 관련 파일
- `core/files.py`
- `core/processing.py`

### 저장물
- md 파일
- 청크 텍스트
- 상태 정보
- 품질 로그

### 원칙
- 저장 파일은 다시 읽을 수 있어야 한다.
- 사람과 기계가 모두 다루기 쉬워야 한다.

---

## 6단계: 임베딩

### 역할
청크를 벡터로 변환한다.

### 관련 파일
- `dbma_rag.py`
- `core/processing.py`

### 기본 기준
- 임베딩 모델: `bge-m3:latest`

### 출력
- 벡터 표현
- 검색용 인덱스
- 저장된 임베딩 결과

---

## 7단계: 검색

### 역할
질문과 관련된 청크를 찾는다.

### 관련 파일
- `dbma_rag.py`

### 주요 작업
- 질의 인코딩
- 벡터 검색
- 필요 시 키워드 검색 보조
- 결과 정렬

### 출력
- 관련 청크
- 점수
- 검색 로그

---

## 8단계: 생성

### 역할
검색 결과를 바탕으로 답변을 만든다.

### 관련 파일
- `dbma_rag.py`

### 주요 작업
- 프롬프트 구성
- LLM 호출
- 응답 생성
- 출처 표시

### 출력
- 답변 텍스트
- 인용 정보
- 응답 품질 로그

---

## 9단계: 평가

### 역할
결과가 기준에 맞는지 확인한다.

### 관련 파일
- `loops/`
- `scripts/`
- `docs/`

### 주요 작업
- 목표 대비 결과 확인
- 실패 원인 기록
- 다음 반복 계획 작성
- 진행률 갱신

### 출력
- 평가 기록
- 체크포인트
- 다음 조치

---

## 10단계: 문서화

### 역할
실행 결과와 상태를 문서로 남긴다.

### 관련 파일
- `docs/TODO.md`
- `docs/STATE.md`
- `docs/ARCHITECTURE.md`
- `docs/DBMA_MAP.md`

### 주요 작업
- 상태 기록
- 진행률 업데이트
- 구조 변경 반영
- 새로운 규칙 추가

---

## 반복 루프

DBMA는 단발성 처리보다 반복 개선에 맞춰 설계한다.

```text
목표 설정
→ 실행
→ 검토
→ 수정
→ 재실행
→ 안정화
```

이 루프가 루프 엔지니어링의 핵심이다.

---

## 점검 기준

- 입력에서 출력까지 끊기지 않는가.
- md 파일이 실제로 생성되는가.
- 청킹 기본값이 유지되는가.
- 검색과 생성이 분리되어 있는가.
- 평가와 문서화가 반복 가능한가.

---

## 작성 규칙
- 파이프라인은 실제 동작 기준으로 기록한다.
- 파일명이 바뀌면 문서도 함께 바꾼다.
- 불필요한 이론 설명보다 실무 흐름을 우선한다.
- 실행 순서가 바뀌면 이 문서도 갱신한다.

**작성일:** 2026-09-15
**전제:** 전액 무료 배포 (수익화 없음)
**성격:** 제안 — HQ 결정 필요 항목 §6에 정리
**진행률:** 0% (검토 대기)

## 1. 결론 요약

**이 앱은 무료 배포에 구조적으로 유리하다.** 로컬 실행(Ollama) 아키텍처라 사용자가
늘어도 서버 비용이 0이다. 상업 제품(Logos·Sermonary·Pulpit AI)이 월 $39~99를 받는
이유가 API·서버 비용인데, 내서재는 그 비용 자체가 발생하지 않는다.

따라서 무료 배포의 장애물은 **돈이 아니라 세 가지**다:

| 장애물 | 성격 | 난이도 |
|---|---|---|
| 저작권 — 무엇을 동봉할 수 있는가 | 법적 차단선 | **높음** |
| 설치 마찰 — 목회자가 혼자 설치 가능한가 | UX | 중간 (자산 양호) |
| 지원 부담 — 1인 개발자가 감당 가능한가 | 지속가능성 | **높음** |

## 2. 저작권 — 무료 배포의 최대 쟁점

### 2.1 원칙

**무료 배포는 저작권 면책 사유가 아니다.** 대가를 받지 않아도 복제·배포는 침해다.
오히려 배포 범위가 넓어져 위험이 커진다.

### 2.2 동봉 가능 여부 판정

| 자산 | 동봉 | 근거 |
|---|---|---|
| 상용 전자책 주석·조직신학 (Calibre 장서 122권) | ❌ **절대 불가** | 유통 전자책. 개인 소장 ≠ 배포권 |
| NAE 트랙 — Fuller 8권·Dagg·Hiscox·Smith 4권·1689/1742/1765 | ✅ **가능** | 전량 퍼블릭 도메인 |
| 한글 성경 본문 (`data/bible/`) | ⚠️ **확인 필수** | 개역개정은 대한성서공회 저작권 존속. 개역한글도 판본별 쟁점 |
| `data/beta_corpus/` (156M) | ⚠️ **확인 필수** | 출처 미검증 — 배포 전 전수 확인 |
| 사용자 본인 장서 | ✅ | 각자 기기에서 각자 처리 |

**2026-09-15 데이터 리셋으로 프로덕션 코퍼스가 비워진 것은 배포 관점에서 오히려 유리하다.**
동봉할 것이 없는 상태에서 시작하므로 "실수로 상용 자료가 패키지에 섞여 나가는" 사고가 원천 차단된다.

### 2.3 권장 구성 — 3단 서재

```
① 기본 동봉 (퍼블릭 도메인)      NAE 트랙 — 즉시 사용 가능한 최소 서재
② 선택 다운로드                   목회자가 앱 내에서 받는 추가 공개 자료
③ 본인 장서                       목회자가 직접 넣는 자기 책 (앱은 처리만)
```

③이 이 앱의 정체성이다. "우리가 자료를 주는 앱"이 아니라 **"당신의 서재를 검색 가능하게
만드는 앱"**으로 포지셔닝하면 저작권 문제가 대부분 사라지고, Logos와도 경쟁하지 않는다.

**성경 본문은 별도 결정이 필요하다.** 한국어 목회자 대상인데 성경 본문 없이는 실용성이
크게 떨어진다. 대한성서공회 사용 허락을 문의하거나(비영리 무료 배포는 허락 사례 있음),
공개 번역본으로 대체하거나, 사용자가 직접 넣게 하는 세 경로 중 선택해야 한다.

## 3. 설치 마찰 — 현 자산은 양호하다

### 3.1 이미 갖춘 것

`scripts/setup_beta_tester.command`가 상당한 수준으로 구현돼 있다:

- 메모리 등급 자동 판정 → 8GB 미만 중단 / 8~16GB `llama3.2:3b` / 16GB+ `llama3.1:8b`
- Ollama 미설치 시 Homebrew로 자동 설치
- 선택된 모델을 `config.yaml` 기본값으로 자동 패치
- `build_mac_package.sh`로 더블클릭 `.app` + `.dmg` 생성

**목회자 대상 배포에 필요한 설치 자동화는 대부분 완성돼 있다.** 새로 만들 것보다
남은 마찰 3가지를 없애는 편이 효율적이다.

### 3.2 남은 마찰

| 마찰 | 현상 | 대응 |
|---|---|---|
| Gatekeeper 경고 | 무서명 DMG → "확인되지 않은 개발자" | §4에서 결정 |
| 모델 다운로드 3~5GB | 첫 실행까지 수십 분, 교회 인터넷에서 실패 가능 | 진행률 표시 + 재개 지원 + 실패 시 안내 |
| Homebrew 의존 | 목회자 Mac에 없을 가능성 높음 | Ollama 공식 `.dmg` 직접 설치로 대체 검토 |

### 3.3 최소 사양 현실화

`INSTALL.md`는 RAM 최소 4GB로 안내하나, 설치 스크립트는 8GB 미만을 중단시킨다.
**문서와 실제가 불일치한다.** 배포 전 8GB로 통일하고, 8~16GB 구간의 체감 속도를
실측해 안내에 명시해야 한다(3b 모델의 설교 생성 품질은 별도 검증 필요).

## 4. 서명·공증 — 비용 대비 결정

2026-07-28에 "Apple Developer 전환 없이 무서명 DMG 유지"로 결정된 바 있다.
**무료 배포로 대상이 넓어지면 이 결정을 재검토할 가치가 있다.**

| 방안 | 비용 | 목회자 체감 | 평가 |
|---|---|---|---|
| A. 무서명 DMG (현행 결정) | 0원 | 우클릭→열기 1회 필요. 안내 없으면 설치 포기 발생 | 기술 친숙 목회자 한정 |
| B. Apple Developer 서명+공증 | **연 $99** | 더블클릭으로 끝 | 무료 배포여도 이 비용은 발생 |
| C. GitHub Releases + 설치 안내 영상 | 0원 | A와 동일하나 이탈률 개선 | A의 보완재 |

전액 무료 배포에서 유일하게 발생하는 실질 비용이 B다. **연 $99로 설치 이탈률을 얼마나
줄이느냐의 문제**이며, 배포 규모가 수십 명이면 A+C로 충분하고 수백 명 이상이면 B가 합리적이다.

## 5. 지속가능성 — 진짜 비용은 지원이다

무료 배포에서 개발자가 실제로 지불하는 것은 서버비가 아니라 **문의 대응 시간**이다.
1인 개발 체제(메모리: CUE↔C1 무인 loop 불가 확정)에서 이것이 유일한 확장 제약이다.

**대응 설계**

- 앱 내 `도움말` 페이지를 1차 방어선으로 — 흔한 오류 5가지는 이미 `INSTALL.md`에 정리됨
- 자가 진단 버튼 — Ollama 상태·모델 존재·디스크 여유를 앱이 스스로 점검해 보고
- 문의 창구를 **비동기 단일 채널**로 한정 (이메일 또는 GitHub Issues). 전화·카톡 금지
- "지원 보증 없음(as-is)" 명시 — 무료 배포의 전제 조건으로 배포 문서에 기재
- 기수제 배포 — 상시 배포 대신 분기 1회 등 묶어서 내면 대응이 집중되어 부담이 준다

## 6. 배포 차단 항목 (해결 전 배포 불가)

| # | 항목 | 현황 | 비고 |
|---|---|---|---|
| B-1 | **빈 코퍼스 상태의 설교 생성 안전장치** | 미적용 | 코퍼스가 빈 상태에서 설교문을 생성하면 근거 없이 LLM이 작성한다. 목회자가 그것을 강단에서 쓰면 실질 피해. 자료 0건일 때 생성 차단 또는 강한 경고 필요 |
| B-2 | **RAG 보안 체크리스트 5건** | 미적용 | 배포 전 적용 예정으로 기록돼 있으나 미수행 |
| B-3 | **인용 메타데이터 null** | 미해결 | `title`/`author`가 비어 출처 표기 불가. "출처를 확인할 수 있다"는 `INSTALL.md` §7 설명과 실제가 불일치 |
| B-4 | **동봉 자산 저작권 전수 확인** | 미수행 | `data/beta_corpus/` 156M, `data/bible/` 4.9M 출처 확인 |
| B-5 | 최소 사양 문서·코드 불일치 | 미해결 | 4GB(문서) vs 8GB(스크립트) |

**B-1이 가장 시급하다.** 리셋으로 코퍼스가 빈 지금, 앱을 그대로 배포하면 모든 사용자가
근거 없는 설교문을 받게 된다.

## 7. 단계 계획

```md
- [ ] Phase A  법적 정리      B-4 저작권 전수 확인 + 성경 본문 경로 결정
- [ ] Phase B  안전장치       B-1 빈 코퍼스 생성 차단 + B-3 인용 표기 + B-2 보안
- [ ] Phase C  동봉 서재      NAE 퍼블릭 도메인 트랙을 배포용 최소 서재로 구성
- [ ] Phase D  설치 마감      Gatekeeper 방안 결정(§4) + Homebrew 의존 제거 + 사양 통일
- [ ] Phase E  소규모 검증    목회자 3~5명 실기기 설치 테스트
- [ ] Phase F  공개 배포      GitHub Releases + 설치 안내
진행률: 0%
```

Phase A·B는 순서를 바꿀 수 없다 — 법적 정리와 안전장치 없이 배포하면 되돌릴 수 없다.

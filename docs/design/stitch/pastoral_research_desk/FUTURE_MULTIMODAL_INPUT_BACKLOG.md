# 향후 판올림 — 다중입력 인식 기능 백로그

> 결정: 2026-08-20, Rev. Bang. 지금 구현 착수 아님 — **다음 큰 판올림**에서
> 개발. 이 문서는 그때까지의 조사 결과를 보존하기 위한 기록.

---

## 1. 기능 개요

설교자의 개인 작업 문서(손글씨 메모, 마인드맵 형식 노트, 음성 메모/명령)를
읽어 저자 본인의 의향을 근거 기반으로 추론하고, 설교 구조 초안을 만들어주는
입력 다중화 기능. 세 가지 입력 모달리티를 하나의 기능 묶음으로 취급한다.

1. 손글씨 이미지
2. 마인드맵 형식의 구조형 노트
3. 음성 메모 + 음성 명령

---

## 2. 핵심 설계 원칙 (전 모달리티 공통)

- **근거 기반 추론**: "저자의 의향 간파"는 순수 추측이 아니라, 저자 본인의
  기존 등록 자료(설교/노트)를 RAG로 검색해 과거 패턴을 근거로 제시하는
  방식으로 설계한다. 근거 문서를 함께 노출하여 추적 가능하게 한다.
- **초안 원칙**: 모든 출력은 확정이 아니라 초안이며, 사람이 확인·수정하는
  단계(`sermon_research_hub.html`의 "개요 초안 → 수정 → 다시 생성" 패턴)를
  반드시 거친다.
- **근거 부족 경고**: 저자의 과거 자료가 적으면 추론이 일반 지식으로
  회귀하므로, 최소 근거 문서 수 임계치 미달 시 "근거 부족" 표시가 필요하다.

---

## 3. 모달리티별 조건

### 3.1 손글씨 이미지

- 기존 `core/extractors.py`의 `_extract_via_ocr`(pytesseract)는 스캔본
  활자 OCR 전용이라 필기체엔 부적합 — 별도 vision-LLM 기반 전사 경로 신설
  필요.
- 전사 결과에 판독 불확실 구간 마킹 필요(오독을 근거로 쓰지 않도록).

### 3.2 마인드맵 형식 노트

- 선형 텍스트 OCR로는 부족 — 노드/화살표/계층 관계를 읽으려면 이미지
  전체를 vision-LLM에 넣어 **구조를 직접 추론**해야 함(텍스트 전사와는
  출력 스키마가 다름).
- 입력 유형 분류(선형 노트 vs 구조형 다이어그램) 전처리 단계 필요.
- 오인식 시 설교 논지 구조 자체가 뒤집힐 수 있어 원본 이미지와 추출된
  구조를 나란히 대조 확인하는 UI가 필수.
- 추출 결과는 "뼈대"이지 "본문"이 아니므로, 곧장 설교 개요로 승격시키지
  않고 저자 코퍼스 근거를 붙인 제안 형태로 제시한다.

### 3.3 음성 메모 + 음성 명령

- STT(예: Whisper류)는 이미지 인식보다 성숙도가 높아 상대적으로 가벼운
  조건 — 전사 후 파이프라인은 손글씨/텍스트 경로와 대부분 재사용 가능.
- 구어체 특성(중복, 머뭇거림, 비문)으로 인한 노이즈 제거를 위해 전사 후
  "핵심 논지 요약" 경량 전처리 단계 필요.
- **음성 명령 처리**: 콘텐츠 입력(음성 메모 전사)과 별개로, 조작 명령
  (예: "이 자료 설교 연구에 추가해줘", "검색해줘") 인식도 지원 범위에
  포함 — 명령 인텐트 분류가 콘텐츠 전사와 별도 경로로 필요.

## 4. 아키텍처 조건

- 이는 신규 소스 타입(이미지/음성) + 신규 추출 경로 추가에 해당한다.
  ADR-020 §12는 "discovery→registration→OCR→first-TSU"를 이미
  out-of-scope로 명시했고, ADR-021은 그 일부(Registration~Extraction)만
  구현했다. 손글씨/마인드맵/음성 인식은 ADR-021의 Extraction 단계 확장으로
  봐야 하며, **Approved ADR을 직접 수정하지 않고 신규 Amendment 문서**를
  먼저 작성·승인받아야 한다(Architecture Freeze Rule 적용 대상).
- 원본(이미지/오디오) 보존은 기존 Raw Preservation 정책과 동일하게
  적용한다(원본 삭제 금지).
